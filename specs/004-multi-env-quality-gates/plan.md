# Implementation Plan: Multi-Environment Bicep Pipeline with Approvals

**Branch**: `004-multi-env-quality-gates` | **Date**: 2025-01-01 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/004-multi-env-quality-gates/spec.md`

---

## Summary

Add a PR-triggered GitHub Actions workflow (`004-multi-env-ci.yml`) that
runs a sequential, seven-job Bicep deployment pipeline across three Azure
environments — dev → qa → prod — with GitHub Environment approval gates
blocking promotion to qa and prod.  Bicep parameter files for all three
environments exist in `bicep/`.  The remaining work is wiring GitHub
Environments, branch protection, and ensuring the untracked workflow file is
committed.

---

**Language/Version**: YAML (GitHub Actions), Azure Bicep

**Target Platform**: GitHub Actions (ubuntu-latest), Microsoft Azure  
**Project Type**: CI/CD pipeline  
**Performance Goals**: Each job fast — validate ≈ 10–30 s; what-if ≈ 30–60 s; deploy ≈ 1–3 min  
**Constraints**: PR-only trigger; sequential job chain; no third-party actions  
**Scale/Scope**: 3 environments, 7 jobs, 3 parameter files

| IV. Simplicity | Native GitHub Environments used for gates; no third-party approval actions; one responsibility per job | ✅ PASS |
| V. Tested | `validate` job runs `az deployment group validate` on every PR; what-if stages surface changes before apply | ✅ PASS |

**All gates pass. Constitution III deviation (human approval gates) is acknowledged and accepted — see spec.md NF-2.**

## Phase 0 — Research (Complete)

See [`research.md`](research.md).

Key decisions resolved:

| Unknown | Resolution |
|---------|-----------|
| Bicep "plan" equivalent | `az deployment group what-if` — native Azure CLI, no extra tooling |
| Approval gate mechanism | GitHub Environment protection rules (required reviewers) in Settings |
| Concurrency pattern | Reuse existing `${{ github.workflow }}-${{ github.ref }}` + `cancel-in-progress: true` |
| Parameter strategy | One committed JSON file per environment; secrets stay in GitHub Secrets |
| Branch protection | GitHub repo Settings → Branches; not configurable from workflow YAML |

## Phase 1 — Design & Contracts (Complete)

### data-model.md

Documents:
- Stage dependency graph (validate → plan-dev → deploy-dev → plan-qa → deploy-qa → plan-prod → deploy-prod)
- Environment parameter matrix (SKUs per env)

- GitHub Environment configuration table
- Required Bicep resource tags per Constitution II

### contracts/workflow-contract.md

Documents:
- Trigger contract (PR to main, cancel-in-progress)
- Per-job interface (needs, environment, Azure CLI command)
- Parameter file JSON schema
- GitHub Environment contract (protection rules, variable inheritance)
- Output contract (deployment outputs printed to log; not passed between jobs)

### quickstart.md

Step-by-step manual setup:
1. Create GitHub Environments (dev, qa, prod)
2. Add required reviewers to qa and prod environments
3. Configure branch protection on main (require PR + `Bicep Validate` status check)
4. Verify end-to-end via a test PR
